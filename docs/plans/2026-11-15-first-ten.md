# Workbench: first ten roadmap items

## Scope

Deliver TES-267 through TES-276 in four coordinated workstreams. The current request authorizes implementation and GitHub delivery. Earlier design-only directions in the source documents are reference history.

1. Result review: explicit product result, repository launch recipe, health and recovery, stable Needs you filter, next-decision command.
2. Honest state and permissions: independent activity and outcome, unknown status, Review request label, exact provider permission wording with terminal review when scope is unknown.
3. Safe commits: named files, exact target and immutable content, explicit review, stale-state refusal, hooks and signing retained.
4. Finish and launch recovery: acceptance/checks/publication summary, protected cleanup proposal, merged-task archive, cancelled launch preserves destination, missing CLI setup in the sheet.

## Constraints

Use the existing native shell, preview/process owner, protocol services, actor isolation, shared GitHub observations, and SQLite metadata store. Do not introduce another dashboard or infer product acceptance from an idle agent, passing check, or merged PR. No automatic publication or resource deletion follows product acceptance. Protect active, dirty, unmerged and unknown work. No installation, merge, actual cleanup, or force operation is part of this delivery.

## Verification

Investigate each ticket and owning source, independently verify implementation specifications, implement, independently review actual changes, and return findings to the implementer. Run affected unit suites, repository motion/shell guards, the full local test gate and final app compilation. GitHub CI is unavailable and cannot substitute for local checks.

TES-266 remains an outstanding real-user validation exercise. Automated checks do not establish participant recognition, five-second blocker discovery, one-action comprehension, or a 90% launch success rate. Record those measurements only after actual observations.
