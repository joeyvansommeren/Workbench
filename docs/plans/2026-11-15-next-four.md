# Workbench: launch settings and review clarity

## Goal and scope

Implement four additional Linear tickets in three independent workstreams. The base is the published first-ten commit `ee3fc3f27f6c111002c333c5c34892649286abf8`. Delivery is a separate pull request based on `codex/workbench-first-ten`; it must not include duplicate first-ten changes in its review diff.

### Claude launch settings

Turn off Claude agent progress summaries by default for processes Workbench launches. Add an accessible setting to enable them. Apply the environment change locally to the spawned process and preserve other environment and resume contracts. Verify the exact variable against current primary documentation or the installed CLI. Do not claim the reported cost saving as measured fact.

Initial ownership: CLI launch/environment configuration and its tests, the relevant settings surface, and AgentHubDefaults. Investigate SwiftTerm, Ghostty and accessory launch paths before settling the specification.

### Diff and session header

Expose Expand diff as a visible action. Give the changed-file list a bounded independent scroll so code remains visible. Preserve mode selection, file selection, keyboard routing and the existing full-diff destination.

Replace redundant context dots with a clear percentage and keyboard-reachable detail. Keep one useful identity line, retaining target information needed to avoid acting on the wrong session.

Initial ownership: GitDiffView, SessionHeaderView, their narrow presentation helpers and tests, and SessionSidePanel only if the existing expansion callback requires it.

### Reviews clarity

Distinguish Review changes from Ask agent to review. Give Open a neutral badge. Consolidate equivalent display states while retaining source details. Hide unneeded columns, persist user column choices as UI preferences, and prevent title truncation at a 1440-point window. Explain the GitHub Project dependency without implying that absent Projects means absent PRs. Preserve saved rows on refresh failure and named recovery actions.

Initial ownership: Reviews presentation/table/destination files and matching tests. Keep column preferences local to Reviews; AgentHubDefaults is owned by the launch-settings workstream.

## Implementation and verification contract

Each author first investigates owning source and writes a bounded specification. A different agent verifies that specification before implementation. Authors keep exclusive file ownership, preserve unrelated code and make no Git or connector mutations. The orchestrator owns authoritative native tests and commits. Independent reviewers return valid findings to the original author.

Use existing protocols, actor isolation, observable state and native controls. This is a macOS professional workspace. Preserve focus, selection, cancellation, restoration and accessibility contracts. Use existing type/color/spacing tokens; no measured-width feedback, GeometryReader-driven widths, press/hover scaling, new dependencies or new session-management UserDefaults state.

Choose meaningful test-first or characterization evidence before behavior changes. Run all affected native suites, motion/shell guards, the full local gate before publication and a final full app build. Record actual failures and manual verification limits. No CI pass is assumed. Stress long titles, Unicode/emoji, empty and error states, narrow/wide layout and both appearances. Human VoiceOver validation must not be invented.

Remove task-owned generated builds when finished. Archive completed managed worktrees through Codex when allowed; do not bypass primary-checkout protection. Do not merge, install, enable CI, remove legacy UI, or change unrelated tickets.
